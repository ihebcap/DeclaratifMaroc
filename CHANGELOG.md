### TASK-023 — Lecture Sage en session réutilisée + timeout par pièce + isolation d'erreur (APPROUVÉE — re-soumise après rejet)
- **Mode lot `SageTaxReaderService.LireFactures`** : la session COM Sage (`BSCIALApplication100c.Open()`) est ouverte **une seule fois** sur un **unique thread STA** dédié qui consomme les pièces une à une depuis une `BlockingCollection` (`1 OpenSession → N ReadPiece → 1 CloseAndRelease`), là où l'ancien code payait un `Open/Close` complet **par facture** (coût dominant). Devise société et types de taxe (`cacheTypesTaxes` par code) **cachés hors boucle** (invariants du lot). Libération COM par pièce (`Marshal.ReleaseComObject(doc)` en `finally`) + session libérée en fin de lot. **❌ Aucun `Parallel.ForEach` / multi-session** — contrainte d'architecture (licences/verrous COM) respectée.
- **Timeout PAR PIÈCE rétabli (correctif du rejet)** : le 1er passage avait dégradé le timeout unitaire (30 s) en **timeout global unique (~8h)**. Le thread appelant réimpose 30 s par pièce via `SemaphoreSlim.Wait(perPieceTimeout)` ; le thread STA est `IsBackground` (un STA figé meurt à la sortie du worker), plus de gel global possible.
- **Isolation d'erreur (correctif du rejet — drop silencieux `Console.Error.WriteLine` + skip supprimé)** : helper `EntreeEnErreur(req, motif)` + ajout DTO minimal `bool EnErreur` / `string MotifErreur` (rétro-compatible JSON). Une pièce introuvable / sens inconnu / exception COM / **timeout** ressort avec sa clé `piece_sens` **présente** → N traité = N demandé, zéro disparition. Sur exception la boucle **poursuit** ; sur timeout (STA figé, irrécupérable) le lot est arrêté proprement (`lotInterrompu`) et **les pièces restantes ressortent en erreur** avec le motif d'interruption.
- **Branchement consommateur (aucune ligne silencieuse ni ventilation fausse)** : `ConstructeurDeclaration` — une facture `EnErreur` n'est jamais ventilée, elle produit une alerte `Error` `FACTURE_ILLISIBLE_OM` portant le `MotifErreur` exact ; `OrchestrateurDeclaration` — garde `if (doc.EnErreur) continue;` avant toute matérialisation cache SQL (jamais de cache d'une pièce KO).

### TASK-028 — Verrou d'intégration déclaration (tampon `DT_Id` + triggers d'immuabilité) (APPROUVÉE — re-soumise après rejet PO)
- **Garde-fou base, portée globale GRFN inclus** : `003_Verrou_DT_Id.sql` pose deux triggers T-SQL set-based sur la base partagée. `TR_RT_AFFECTATION_Immuabilite` refuse le DELETE et l'UPDATE financier/structurant (`AF_Montant`, `MV_Id`, `EC_Id`, `AF_Date`) d'une affectation `DT_Id NOT NULL`, tout en **autorisant explicitement** les transitions `DT_Id` valeur→NULL (réouverture) et NULL→valeur (intégration). `TR_RT_MOUVEMENT_Immuabilite` refuse le dérapprochement (`MV_Point 1→0`) et la décomptabilisation (`MV_Compta 1→0`) de tout mouvement portant ≥1 affectation déclarée.
